## 唯一目标

输入参考类型 A 或 B，以及可选的故事主题和人物关系，输出一份与对应参考在结构和制作参数上相似的原创古装视频脚本。

“相似”只按本文列出的可检查特征判断，不要求技能总结通用创作理论，也不要求判断作品是否高级、感人、适合女性或能够成为爆款。

首版只支持两类脚本：

- A：7-10 秒，冷调、克制、双人重逢或身份确认。
- B：约 47 秒，暖调毁灭场景、冷调闪回、三人高冲突困局。

## 非目标

- 不产出题材战略、账号定位、发布策略或流量预测。
- 不建立通用编剧理论、女性向情绪理论或长剧压缩理论。
- 不输出三个候选方向，除非用户明确要求。
- 不默认输出角色图、分镜图、视频提示词或提交任务；本技能默认只交付脚本。
- 不读取或套用任何本地系列角色和剧情，除非用户明确指定。
- 不复用参考作品的人名、经典台词、具体剧情事件或完整标志性动作链。

当前没有原视频文件、发布链接和后台数据，因此技能只复现文字拆解中明确记录的结构特征，不声称复现了未提供的视频细节。

## 输入契约

### 必填

- `reference_type`：`A` 或 `B`。

### 选填

- `story_seed`：一句故事前提。
- `characters`：人物身份与关系。
- `duration`：目标时长。
- `must_keep`：必须保留的事件、台词或道具。
- `must_avoid`：禁止出现的元素。

### 缺省处理

- 未提供故事前提时，生成一个不引用本地系列的原创前提。
- 未提供人物时，A 生成 2 人，B 生成 3 人。
- A 未提供时长时使用 8 秒；允许范围 7-10 秒。
- B 未提供时长时使用 47 秒；允许范围 45-47 秒。脚本阶段不按视频模型上限拆制作任务。
- 用户要求超出对应范围时，先说明模板限制，再按用户明确的新时长执行；不得静默改时长。

## 固定输出格式

每次只输出一套脚本，顺序固定：

1. **标题与基础信息**：参考类型、总时长、人物数、时空段落数。
2. **一句话剧情**：只写当前视频能表现的事件。
3. **人物表**：姓名、公开身份、当前目标、当前阻碍、服装与识别特征。
4. **逐秒镜头脚本**：时间、景别/构图、动作、表情起点与终点、台词/字幕、光影/声音。
5. **画面风格与视觉质感**：只写能落实到生成或拍摄的参数。
6. **镜头细节与画面元素**：按时间段说明人物、场景、道具和运动。
7. **表情变化与情感传递**：逐人物列出时间点和可见变化。
8. **台词与字幕**：列出完整台词、说话人、出现时间和字幕样式。
9. **结构检查表**：对照对应参考模板逐项标记通过/失败。

不在默认输出中加入创作理论、市场判断、自我评价或后续运营建议。

## 参考 A 特征矩阵

脚本必须同时满足以下条件：

| 项目 | 固定要求 |
| --- | --- |
| 时长 | 7-10 秒，默认 8 秒 |
| 人物 | 2 名主要人物 |
| 场景 | 1 个主场景，不使用闪回 |
| 主镜头 | 2 个；可有不超过 0.5 秒的过渡 |
| 景别 | 近景特写或中近景，不使用远景开场 |
| 色彩 | 低饱和冷调；两人明暗或深浅有可见差异 |
| 光线 | 至少一人使用侧逆光；另一人使用侧光和暗部补光 |
| 背景 | 古风场景虚化，无无关杂物抢主体 |
| 动作 | 全片只有 1 个主要身份揭示动作 |
| 遮挡 | 使用 1 个前景或人物物件完成遮挡到显露 |
| 表情 | 每人至少写出 2 次连续变化，不允许直接从冷漠跳到微笑 |
| 台词 | 1 句，4-12 个汉字，在身份显露后出现 |
| 字幕 | 淡白色，画面下方，不遮挡面部 |
| 声音 | 环境声低于人声；不使用密集旁白解释前史 |

### 参考 A 原创替换项

以下内容不得与参考文本相同：

- 人物姓名和原作身份。
- 白纱与黑色雕花面具的组合。
- “女子先露面、男子摘面具、两人相视微笑”的完整动作顺序。
- 参考中的经典重逢台词。
- 浅青/白与深紫/黑的整套人物配色。

## 参考 B 特征矩阵

脚本必须同时满足以下条件：

| 项目 | 固定要求 |
| --- | --- |
| 时长 | 45-47 秒，默认 47 秒 |
| 人物 | 3 名主要人物，每人有不同的当前目标 |
| 主时空 | 0-15 秒与 26 秒至结尾位于同一高危险场景 |
| 闪回 | 16-22 秒包含 4-6 个短闪回，每个 0.8-1.5 秒 |
| 过渡 | 23-25 秒从闪回回到主时空，并明确女主当前选择 |
| 闪回作用 | 每个闪回证明一种不同的既往失败，不得只展示惨状 |
| 主场景色彩 | 暖橙或其他单一高温危险光源，暗部保留人物细节 |
| 闪回色彩 | 冷调柔光或轻微过曝，与主时空明确区分 |
| 景别 | 主场景以近景特写和中近景为主；闪回使用中景与特写快速切换 |
| 开场 | 前 3 秒出现高情绪动作或台词，并说明一个反常事实 |
| 环境 | 1 个持续存在并参与剧情的危险环境 |
| 道具 | 1 个核心攻击、防御或倒计时道具 |
| 人物冲突 | 3 个目标必须互相阻断，删掉任一人物会改变结局 |
| 主角表情 | 至少 4 个连续状态 |
| 另外两人表情 | 每人至少 2 个连续状态 |
| 台词 | 6-10 句；单句不超过 18 个汉字 |
| 旁白字幕 | 最多 3 条；每条不超过 10 个汉字；只补时间或循环信息 |
| 结尾 | 再次发生失败或回到困局，且新增一个可见代价 |

### 参考 B 原创替换项

以下内容不得与参考文本相同：

- “99 次”循环数字。
- 篡位王爷、白衣太子、柔弱女主的三人关系。
- 火烧宫殿作为危险场景。
- 剑作为核心道具。
- 上吊、被刺、下毒的整组闪回死亡方式。
- 黑、白、浅绿三套服装的对应关系。
- 参考中的全部台词与解释字幕。

## 结构化脚本规则

逐秒镜头脚本使用固定表头：

| 时间 | 时空段落 | 景别/构图 | 人物动作 | 表情变化 | 台词/字幕 | 光影/声音 |
| --- | --- | --- | --- | --- | --- | --- |

每行只允许一个主要动作。需要两个连续动作时拆成两行。表情变化必须写成“起点 -> 触发 -> 终点”，不能只写“深情”“崩溃”或“复杂”。

台词必须直接写出，不得用“说出愤怒台词”“表达爱意”等占位描述。字幕必须注明是否与台词相同，以及颜色和位置。

## 执行流程

1. 读取用户输入。
2. 根据 `reference_type` 只加载参考 A 或参考 B 的规格，不同时混用两种模板。
3. 填充原创人物、事件、场景和道具。
4. 先生成逐秒镜头脚本，再补充视觉、表演和台词说明。
5. 对照对应特征矩阵逐项检查。
6. 任一固定要求失败时，只修改失败项并重新检查。
7. 所有要求通过后交付一套脚本。

## 禁止主观扩写

技能默认不得输出以下内容：

- “这个方向更高级/更戳女性/更有宿命感”等无检查标准的判断。
- “观众一定会哭/会磕/会追更/会爆”等结果承诺。
- 自创的通用创作法命名。
- 与用户当前请求无关的世界观、系列设定和长线剧情。
- 基于两份参考之外的风格补充，除非用户明确要求。

## 技能结构

```text
skills/gg-writing-reference-style-costume-scripts/
  SKILL.md
  agents/openai.yaml
  references/reference-a-spec.md
  references/reference-b-spec.md
  references/script-output-template.md
  references/validation-checklist.md
  scripts/validate-script-structure.py
```

- `SKILL.md`：输入路由、执行顺序、输出限制。
- `reference-a-spec.md`：参考 A 的完整特征矩阵与原创替换项。
- `reference-b-spec.md`：参考 B 的完整特征矩阵与原创替换项。
- `script-output-template.md`：固定 Markdown 输出模板。
- `validation-checklist.md`：人工可读的通过/失败清单。
- `validate-script-structure.py`：检查时长、时空段落数、镜头表头、人物数、台词数和必填章节；不评价情绪质量。

## RED-GREEN 验证

### RED：无技能基线

使用同一组输入分别生成：

1. A 类 8 秒双人古装重逢脚本。
2. B 类 47 秒三人高冲突古装脚本。

记录特征矩阵中缺失或超限的项目，不做主观评分。

### GREEN：加载技能

使用完全相同的输入再次生成。通过标准：

- A 类特征矩阵全部通过。
- B 类特征矩阵全部通过。
- 固定输出 9 个章节齐全。
- 结构校验脚本返回成功。
- 未出现两份参考中的禁用人物、台词、剧情事件和完整动作链。
- 未读取或复用任何本地系列角色和剧情。

- A、B 两类技能输出全部通过对应特征矩阵。
- 结构校验脚本测试通过。
- 默认交付只有一套视频脚本，不附带无关策略、理论或主观评价。
