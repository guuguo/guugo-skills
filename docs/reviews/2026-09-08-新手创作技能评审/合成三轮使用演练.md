# 新手三轮使用演练（仅合成，不是真实案例或用户测试）

这份文件由评审 Agent 按当前技能进行桌面演练。CLI 搜索是真的运行了；所有作品、事件、播放数都是临时测试数据，非媒体源只用于通过文件存在检查，不曾观看原视频。不证明真实视听理解、爆款检索质量、用户满意度或成片可拍性。

## 第 1 轮

输入：给我找乡村双男主第一集初遇的相似爆款参考，两个男主都有主见，别把一个写成只能等人救。我要先看原例，别给我创作方向。

实际工具：CLI --config 本临时目录/config.json search --term 乡村 --term 双男主 --term 初遇，召回 3 条，详见 search-output.json。

遵循技能的 Agent 处理：
- 读取 3 个完整 JSON；排除“河边搭救”，理由为乙没有主动选择。不能因为其合成播放量最高就推荐。
- 保留“窄路错车”和“争水到轮灌”，在本演练里分别编号 1、2。两者都有相反目标、自己提出解决办法且承担代价；必要前提是第一次相遇时双方能就具体事务谈判。
- 每条呈现已有的完整发生过程、目标、选择、回应、结果、00:00–01:00 范围和合成指标，但必须明确“这不是原作证据，不能作为你要求的真实参考”；未得到逐字对白和画面，不允许编成原文补全。
- 正式空库则只能报告 0 条，不能用这些合成案例给正式检索补位；本轮真实目标没有闭环。

用户仍需承担：有真实素材时，比较哪个回合/人物选择让自己想看下去并选例；无需自己拆机制、搜关键词或填标签。现状还需触发后续扩采才能继续。

## 第 2 轮

输入：第二条有感觉，但我不会改，帮我做成 60 秒能拍的，别只换人名。

进入纯合成创作演练，所选是上轮编号 2“争水到轮灌”，不误称真实参考。

技能直接提供的改造顺序：抽取共同资源冲突、互相付出可见代价而形成有限信任的机制；为甲乙补局部动机；重建动作回合；检查初见的知识及关系边界；检查时长。用户没有正式人物资料，使用暂定人物动机，不能声称已符合既有角色性格。

评审 Agent 补出的提案（以下是本 Agent 的创作，不是技能原文，也不是媒体生成）：

单场景村边灌渠。甲是今天必须试水的返乡种植户；乙在下游育苗，拦闸为了自己两个月的苗，不是逞强等救。两人第一次见。目标从“彼此妨碍”到“各退一项，愿意明早再一起干”。

0–8 秒：甲手压闸杆。乙拿来一盘刚浸坏的苗放闸上。乙：“你这一开，我这两个月就白干。”甲停手看苗。
8–18 秒：甲：“我上头再不浇，今天也白干。”乙拿起两块窄木板：“先过这么宽的水。多了我堵。”甲看一眼木板缺口。
18–28 秒：甲把自己用来垫工具的橡胶片递过去：“这块垫上。你那木板漏。”乙接过试一下，没再顶嘴。
28–40 秒：乙蹲低卡板，甲缓缓抬闸。水碰到乙手指，乙立刻打手势，甲压回；二人重新给木板换位置。（水与板的连续性、动作先后须制作验证。）
40–50 秒：乙：“今天先这么点。明早我给你挖条岔沟。”甲：“你定点，我带锹。”甲松开手，先看一眼乙才起身。
50–60 秒：乙把橡胶片要还甲。甲指木板：“先留这。”乙把工具挪出一处干地方。甲把自己的包放下。结束于可以继续共事，没有一见面就许诺终身。

机制保留：目标相撞，各自提出办法，实际让步形成局部信任。
表达重建：取消用钥匙作押的谈判，变成小流量试水、发现漏洞、共同承担现场后果；各自主见通过提方案和纠正方案表现。

检查结果：时间格合计 60 秒只是纸面分配。没有配音实读、镜头动作计时、目标视频模型、角色参考或生成试验，不可证明能在 60 秒可拍。镜头、水流、蹲姿、手与木板的复杂度需要再处理。本 Agent 自行加入时间格和制作疑点，当前 retrieval.md 没有要求这种交付形态或规定何种检查后能称为可拍。

用户仍需承担：暂定人物是否喜欢、相处方式有没有吸引力、能否接受这类具体日常冲突。对“我不会构思”的用户，人物动机可以由 Agent 起草，但必须公开为暂定，不能让用户负责先写好人物小传才肯改。

## 第 3 轮

输入：还是没感觉，我说不出哪里不好。

技能明确支持：把本次结果记录为拒绝，保留在当前项目；不可自动升级成全局规则。
技能没有给出：用户说不清时怎样诊断与继续；怎样区别没关系火花、太技术化、节奏拖沓、角色不喜欢；怎样让用户通过可感受的小片段表达，而不强迫回答抽象原因。

严格不编造用户偏好的最小合规结果：记录“拒绝，原因未知”。到这里技能没有指定下一动作，无法仅凭规范保证闭环。

本 Agent 能做但属于额外判断的继续方式：先说“这稿的重心都在修水闸，两人的独特性和相互在意显得薄。我先只改一处互动给你看，其他都保留；这只是我的诊断，不把它当作你的偏好。”然后给原版与一段 10 秒的修改版供直接感受。此方法没有用户响应，本演练无法证明会奏效，也不能回写为已确认偏好。

## 分界

- 工具层证据：正式库 0 条；合成库能召回 3 条，关联合成数据。
- 指令层证据：拒绝救援型案例、不先让选创作方向、区分原例/改造/数据的规则明确；60 秒验证和模糊反馈后的动作没有具体化。
- 分析推断：材料齐备时能降低新手找例和拆机制负担；无法由文档保证成品好看、可拍或长期越写越懂用户。
- 未验证：真实媒体采集/理解、真实爆款质量、真人新手体验、上面提案的实际时长和可生成性。
