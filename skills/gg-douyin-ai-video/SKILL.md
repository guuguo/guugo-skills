# 抖音 AI 视频

## 目标

把抖音 AI 视频任务路由到一个明确能力，按唯一生产真源完成工作。情绪叙事优先级为：`钩子与停留 → 情绪起伏与共鸣 → 最低理解 → 结构与生产规整`。非情绪叙事不强套泪点，但仍要求开场状态清楚、动作可见、镜头可执行。

始终区分：可复核事实、工作假设和本项目决定。单条爆款、评论或互动数据只能提供候选机制，不能证明某种写法必然获得流量。

## 启动协议

每次使用本技能，先完整读取：

1. [`references/runtime-contract.md`](references/runtime-contract.md)：规则优先级、默认配置、评审分权和执行回执；
2. [`references/capability-map.md`](references/capability-map.md)：十二种能力的触发条件、输入、输出、所需参考和副作用。

随后执行：

1. 选择一个主能力；确有必要时再选择辅助能力，不把十二种能力全部加载；
2. 解析用户要求和项目真源，输出简短的执行前回执；
3. 只读取能力表中列出的参考文件和当前任务必需的证据；
4. 在授权范围内完成任务；
5. 输出完成回执，列出实际读取、文件变更、外部操作、独立评审状态和未解决问题。

禁止先执行、后补报模式和副作用。案例、示例和历史项目不能覆盖运行合同或能力合同。

## 共同创作原则

### 情绪叙事

先锁定全片最强的 5–15 秒情绪爆发点，再倒推：

`余波 → 对方反应 → 有代价的选择 → 最后一层阻止 → 期待落空 → 关系缺口 → 开场触发`

完整故事至少回答：

- 谁和谁；
- 此刻发生什么；
- 真实阻力为什么不能靠解释消除；
- 谁当场做了什么有代价的选择；
- 对方第一次看见这个动作时为什么会痛、燃、释然或崩溃。

开场前三至五秒必须形成可复述的具体追看问题。金句、大字、哭喊、危险、结果前置、反常动作都可以使用；只检查它们是否提高停留、理解或情绪，不按“像不像 AI”机械扣分。

### 可视化和视频单元

脚本只写模型可生成或听见的画面、动作、表情、声音和切镜，不写作者意图、观众感受或抽象心理。

脚本、分镜和视频提示词的导演编译统一交给 `$ai-video-director-prompt`。进入 C06“可生产脚本编译”或 C07“视频模型适配”时，必须先完整读取该技能及其按需引用的镜头语言参考；本技能只保留任务路由、剧情真源、授权边界、资产与运行适配，不再另设景别、运镜、守轴、表演链、切法或动作音效模板。项目已有固定字段时保留项目结构，把 `$ai-video-director-prompt` 的导演信息写入对应字段。

删除“首帧为”“本单元是”等生产元话时，不得顺带删除导演与音轨信息。每个视频单元至少保留起始景别与机位、必要运镜、内部切镜及承接、动作落点、背景音乐状态、环境声和关键动作声；这些信息直接写进场景与动作，不另套空泛模板。

视频生成单元是一次模型调用产生的一段独立视频文件，不是剪辑镜头。没有项目覆盖时，每个单元优先为 `5–15秒`；同一场景或连续时间线中的反打、硬切、动作跳切、声音桥和短闪回写在单元内部。只有主要场景、核心动作或人物身体状态明显改变，并形成可独立生成的动作胶囊时才拆新单元。

角色身份、年龄和外貌优先由已绑定参考图承担，不在对白旁重复。普通话、无明显口音、正常呼吸和日常状态属于默认值，不写进提示词；人物名后的括号只保留会明显改变本句声音或表演的特殊状态，例如呛咳、哭腔、受伤、剧烈喘息、隔墙喊话。旁白、心声、电话录音、画外声和广播等特殊声源必须明确。

## 角色卡路由

角色卡、人物设定图、身份母版、锁脸卡、多表情卡、定妆照和角色三视图统一交给 `$gg-character-card`。进入 C08 时先读取该技能，由它维护模板选择、参考图职责、提示词和图片验收；本技能不再维护角色卡模板。原角色资产参考文件仅作兼容跳转。

## 正式评审边界

创作者预检与正式评审是两个阶段：

- 创作者预检只能发现明显风险，不能打分、判定放行或冒充独立盲测；
- 凡要标记为“正式候选”“可进入生产”，必须由未参与当前稿创作的独立子代理评审锁定版本；
- 正式评审只输出 `PASS／REVISE／BLOCK` 和证据，不自动改稿；
- 用户授权修改后，由主代理改写，再对新版本重新送审；旧结论不得沿用；
- 没有可用子代理时，只能标记“主代理预检／未完成正式评审”，不得静默降级。

不得使用未经真实项目数据校准的百分制、人口权重、代理留存或固定阈值淘汰、升级或放行故事。候选比较使用硬门、证据、相对优先级和明确理由。

## 证据路由

- 需要可复核的源片、时长、镜头或声音事实：读取 [`references/verified-evidence.md`](references/verified-evidence.md)。
- 需要选择已复盘案例：先读取 [`references/case-library.md`](references/case-library.md)，再只打开最多两篇直接相关案例。
- 需要分析评论和互动结构：读取 [`references/audience-resonance-evidence.md`](references/audience-resonance-evidence.md)。
- 需要采用经验性创作方法：读取 [`references/working-hypotheses.md`](references/working-hypotheses.md)，并把它们标为假设而非规律。

用户提供的脚本、素材、成片、项目配置和后台数据优先于案例。需要当前热点、规则、平台数据或真实事件时必须联网核验；记录来源和采集时间。

## 授权与停止条件

- 分析、诊断和评审任务不自动改稿、改文件或操作外部平台。
- 改写、落文件、整理画布等任务只执行用户已经授权的范围。
- 任何付费生成、发布、删除或难以恢复的外部操作都需要明确授权，并遵守对应工具技能。
- 发现问题时只给最低成本修法；不把局部修正扩张成用户未要求的整套重构。

## 完成检查

- 本轮主能力、加载参考和副作用是否在执行前公开；
- 最终画幅、视频单元和项目锁定项是否来自同一优先级链；
- 正式评审是否由独立子代理针对当前锁定版本完成；
- 是否用未校准数字替代了证据判断；
- 历史案例是否只作证据，没有覆盖当前合同；
- 任务结束时是否报告实际变更、外部操作和剩余风险。
