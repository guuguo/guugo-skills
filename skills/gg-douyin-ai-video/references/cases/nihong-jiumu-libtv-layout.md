# 生产案例：《逆洪救母》LibTV镜头岛布局

沉淀日期：2026-08-28（Asia/Shanghai）

> **历史废弃布局，不具有规范效力。** 本文中的`5200×3200`、`6400×3800`、双候选视频节点和动态扩容，只记录当时项目如何形成问题。当前生产必须服从上级合同与`../libtv-shot-node-layout.md`的固定胶囊规范。案例不得覆盖现行尺寸、画幅、节点数量或授权边界。

## 二、这次项目验证出的依赖边界

### 1. 不同镜头中的同图REF不是重复节点

儿子、母亲、旧皮卡和盘山路会被多个镜头重复使用，但每个镜头都保留自己的隔离REF。这样单独替换某一镜的车辆受损图、道路方向图或人物状态时，不会污染其他镜头。

曾经仅凭视觉相同删除跨镜头REF，会破坏镜头隔离和后续替换；因此“图片文件相同”不能作为删除依据。

### 2. 双方案曾共用素材，但当前收敛为唯一视频节点

历史双方案保持同一剧情、对白、时长、图片集合、音频集合和引用顺序，并共用一套START／END／KEYFRAME／REF。这验证了素材不应因提示词差异而复制；但两个常驻视频入口增加了视觉噪音和选择成本。当前决定是只保留动作连续版视频节点，把必要景别、切镜、呼吸镜头、机位和角度直接写入同一提示词。

### 3. 一个小视频内部可以切镜

- S01使用同一视频节点完成拍盖阻拦、儿子大喊、发动机抬转和车辆从窄口通过。
- S02把原S02A／S02B合并为一个12秒视频节点，在提示词内部硬切老屋与驾驶室。
- S03把原S03A／S03B／S04合并为一个15秒节点，前三秒快切行驶状态，随后集中完成撞击、电话失声、熄火和启动失败。

只有当总时长、动作负载和模型上限允许时才合并；“同一场景”本身不是合并理由。

### 4. 历史上曾通过扩大空间缓解复杂镜头

本项目的普通胶囊常见素材为：区域说明、START、END、主角、第二人物、车辆、道路、细节图、声音和视频节点。S03历史上曾达到6张图＋1个声音＋2个候选视频节点；即使现在缩减为1个视频节点，旧的`2600×1500`或`3400×1500`仍然偏小，容易出现：

- 标题被截断，操作者难以分清节点职责；
- 参考图挤在视频节点下方，新增受损图或音频时只能塞进缝隙；
- 连线穿过其他节点，难以判断实际引用；
- 镜头隔离REF被误判为可删除重复；
- 候选视频入口与跨镜头素材混在一起，选错生成入口。

该项目当时通过扩大镜头岛缓解拥挤，但这一路径已经废弃。当前做法是删除无职责或重复职责REF、压为两行、保留唯一视频节点和2个未来素材槽；仍放不下时报告“素材过载”，不扩大胶囊。

## 三、历史宽松镜头岛（已废弃）

### 历史默认：`5200×3200`（已废弃）

即使当前只有4张参考图，也预留至少2—4个空素材槽：

```text
(0,0)       区域说明／状态／提示词职责

(500,0)     START
(1300,0)    END
(2100,0)    可选KEYFRAME／动作细节

(500,700)   REF｜主角
(1300,700)  REF｜第二人物
(2100,700)  REF｜车辆／核心道具
(2900,700)  REF｜场景／道路

(500,1400)  REF｜动作细节／受损状态
(1300,1400) REF｜补充环境
(2100,1400) REF｜声音
(2900,1400) 预留素材槽

(3900,0)    VIDEO｜动作连续版
(4700,0)    预留执行区／用户明确授权的临时测试位
```

下方`2100—2800`高度继续留给临时对照、补充REF或音频，不把空白视作浪费。

### 历史复杂镜头：`6400×3800`（已废弃）

满足任一条件即升级：

- 图片REF达到6张以上；
- 同时存在START、END和两个以上动作KEYFRAME；
- 有人物声音、环境声音或其他音频REF；
- 需要前后状态、车损、道具细节等多层连续性控制；
- 单视频内部包含三次以上切镜或需要额外呼吸镜头状态图。

复杂镜头至少保留三行素材区和独立视频区；视频节点与最右侧素材之间保留500像素以上空白，避免连线贴边穿过节点。

取消第二视频节点后也不得缩小到旧的紧凑排法。空出的执行位与下方区域继续保留，至少容纳4个未来REF、额外声音或动作状态图。

## 四、历史镜头岛间距（不用于新项目）

- 横向相邻镜头岛建议间隔800—1200像素。
- 纵向换行建议间隔1000—1400像素。
- 每个镜头岛四周保留至少400—600像素空白环。
- MASTER区与正式生产区分开，不从远处MASTER直接拉跨幕长线；每幕建立隔离REF。
- 连线只从左侧素材流向右侧视频，避免折返和跨岛穿越。

这些距离只记录旧画布状态，不是当前默认起点。新项目按`../libtv-shot-node-layout.md`执行。

## 五、镜头岛内的分层

建议固定为四层，使操作者缩放后仍能首遍理解：

1. **说明层**：时间段、剧情职责、动作连续提示词、执行状态、禁令；
2. **分镜层**：START／END／KEYFRAME，按动作时间从左向右；
3. **参考层**：人物、车辆／道具、场景、细节、声音分行排列；
4. **执行层**：一个正式动作连续版视频节点；只有用户明确要求时临时增加A/B测试节点。

历史图、失败图和落败视频不塞在镜头岛空白区；确认淘汰后从画布删除，只在本地问题归档保留。预留空白用于未来生产，不用于堆积废稿。

## 六、当前可迁移结论

- 胶囊尺寸只读取`../libtv-shot-node-layout.md`；旧尺寸不得迁移到新项目。
- 每个胶囊保留唯一正式视频节点和2个未来素材槽。
- 素材过载时先删除无职责REF并压成两行；仍放不下则停止并报告，不动态扩容。
- 跨镜头REF继续隔离；同幕素材只连接到唯一正式动作连续版视频节点。
- 内部切镜在同一提示词中标明景别、切镜方式；只有必要时补机位、角度、毫米焦段和呼吸镜头。
- 只有同一故事版本、同一幕、同一时间段、同一完整职责的废弃组才允许删除。
- 合并视频节点前先验证模型时长和动作负载；通过后在提示词内部按时间段切镜。

该案例只规定生产组织方式，不要求其他故事复制《逆洪救母》的镜头数量、车辆素材或具体切镜节奏。
