# LibTV 视频单元节点布局

## 适用范围

当短片已经进入分镜、素材和视频节点生产阶段，并需要在 LibTV 中创建、整理、替换或删除节点时使用本文件。它只规定画布结构与依赖边界，不替代 LibTV 工具自身的权限、安全和生成规则；实际操作时同时遵守当前环境的 LibTV 专用技能，未经授权不得执行付费生成。

生产案例 [《逆洪救母》LibTV镜头岛布局](cases/nihong-jiumu-libtv-layout.md) 只保留历史问题与迁移记录，不是现行布局规范。除非用户要求复盘该项目，不读取该案例；其中任何旧尺寸、双方案和扩容决定都不得覆盖本文件。

## 核心模型

画布的基本单位不是“一个故事”“一次切镜”或“一张素材”，而是**一次模型调用产出的独立视频胶囊**。没有项目覆盖时，每个胶囊优先为`5–15秒`；内部可以包含多个剪辑镜头、正反打、动作跳切、声音桥和短闪回。成片与素材画幅继承`runtime-contract.md`已经解析的本轮配置，本文件不另设默认画幅。

不得把`1–2秒`切镜、反打或瞬时回忆常态化建成独立VIDEO节点。它们应写进所属视频胶囊的提示词；只有进入新的主要场景、核心动作或稳定身体状态，并形成可独立生成的动作胶囊时才新增区域。

每个小视频胶囊必须拥有一个足够大的独立区域，完整容纳：

- 区域说明；
- 已在本地生成、落盘并上传的 START／END／KEYFRAME 与角色、车辆、道具、场景 `REF`；
- 一个正式动作连续版视频节点；
- 只服务本胶囊的局部连线。

LibTV只做素材编排和视频生成，不做图片生成：

- 图片由 Agent 在本地生成并落盘；
- 验收尺寸和画幅后，使用`libtv upload`上传为`image_resource`节点；
- 画布不创建或保留`image_generate`节点；
- 不存在“角色REF→关键帧图片”之类图片到图片的生成连线；
- 已上传图片只能直接连到所属镜头的正式视频节点；缺图用无连线文字待办说明，不用空图片节点占位。
- 每个VIDEO的提示词必须按`mixedListOrder`在具体动作句中引用`{{Mixed N}}`或对应`{{Node ...}}`；不用“已连线素材锁定……”之类元说明代替逐张职责。

默认结果应做到：缩放到一个区域时，操作者无需寻找远处节点，就能看懂该视频单元使用什么素材、提示词如何切镜、哪个视频节点是唯一正式执行入口。

## 不可破坏的隔离边界

### 跨视频单元：素材隔离

不同视频单元必须保留各自的 `REF` 节点，即使它们引用的是完全相同的底层图片文件。同一视频单元内部的多个剪辑镜头共用该单元的素材区，不为每次切镜复制一座镜头岛。

例如 S03B 和 S04 都使用同一张儿子三视图、同一辆皮卡和同一道路图，也要分别保留：

```text
R128｜S03B｜REF｜儿子38岁
R128｜S04｜REF｜儿子38岁
```

这些不是无意义重复，而是视频单元级依赖隔离。禁止仅凭文件哈希、CDN URL 或视觉相同就跨单元合并。隔离的价值是：

- 单独替换某一镜头的参考图时不会污染其他镜头；
- 每个视频节点的素材归属首遍可懂；
- 画面连续性修复可限定在单一胶囊；
- 删除或重做一个镜头不会破坏其他镜头的提示词引用。

### 同一视频单元：唯一动作连续版视频节点

同一视频单元默认只有一套START、END、角色、车辆、场景和声音素材，以及一个动作连续版视频节点。必要的景别、切镜、呼吸镜头、机位、角度与短闪回全部维护在同一提示词中，不为焦段机位版或内部切镜增加第二个常驻节点。

```text
同一套S01素材
  └─ VIDEO｜动作连续版｜未执行
```

只有用户明确要求临时A/B实验时才增加测试节点。实验结束后先列出落败节点；只有用户明确授权删除时才执行删除并恢复一个正式执行入口，否则保留并标记为待处理。

### 同一视频单元内部切镜：一个视频节点

当 5–15 秒的小视频需要在外景、人物近景、动作特写、电话两端、短回忆和落点之间切镜时，使用一个视频节点，在提示词内部按时间段写切镜，不因每次切镜、地点短暂变化或时间闪回机械拆成多个生成任务。

建议连接：

- START：动作起点与空间关系；
- END：动作完成后的落点；
- 角色身份图；
- 车辆／关键道具图；
- 场景或道路图。

提示词至少写清：时间段、景别、切镜方式、人物动作、环境持续运动、对白与声音、最终落点；空间容易出错或角度承担信息时补机位侧别、高度和俯仰角。呼吸镜头只放在不可逆选择、对方反应或余波处，并保留微动作与环境声。毫米焦段按需要使用，不为了“电影感”堆数字。

### 素材混合引用顺序

同一胶囊先确定一份素材职责清单，再按固定顺序连接到唯一正式视频节点。推荐顺序是：

1. START／主 KEYFRAME；
2. END／第二 KEYFRAME（确有空间落点时才使用）；
3. 主角身份图；
4. 对手角色或第二人物身份图；
5. 车辆／关键道具；
6. 场景／道路／环境。

顺序可以按具体镜头调整。提示词中的`{{Mixed N}}`必须对应实际序号；CLI后台保存为`{{Node 节点ID}}`时，也必须由同一顺序映射，不能凭文字猜序号。

同一胶囊内，底层文件和生产职责都相同的重复节点应列为删除候选；例如主 KEYFRAME 已经完整承担场景与人物站位时，不再新增内容和职责完全相同的场景 REF。已有重复节点只有在用户明确授权删除后才移除。跨视频单元的隔离 REF 仍不得因此合并。

## 区域尺寸与相对布局

节点尺寸和素材数量会变化，但胶囊外框是固定生产约束。以下坐标可在外框内微调，不能扩大外框。默认按“当前必要素材＋2个未来素材槽”规划。

### 统一视频单元岛

所有视频胶囊统一使用精确的`3500 × 1500`画布范围：

```text
区域相对坐标

(0,0)       区域说明
(300,300)   本地上传REF｜主关键帧／主角
(1000,300)  本地上传REF｜第二人物
(1700,300)  本地上传REF｜道具
(300,750)   本地上传REF｜场景
(1000,750)  本地上传REF｜细节／受损状态
(1700,750)  预留REF
(2400,750)  预留REF
(2700,300)  VIDEO｜动作连续版
```

视频节点放在素材右侧，所有已上传图片从左向右直接连到视频节点；区域四周保留约250—400像素空白环。缺失素材用文字待办占位，不创建生图节点。

素材较多时仍使用这一尺寸。规划阶段先排除无职责或重复职责的REF，再将必需素材压成两行，保留唯一视频区和2个未来REF空位；画布上已经存在的冗余节点只列为删除候选，未经明确授权不删除。仍放不下时标记“本单元素材过载”，停止布局并请求删减或分阶段生产；不得静默扩大胶囊，也不得仅为布局方便把一个连续视频单元拆成多个微型单元。

### 多区域排布

- 横向相邻胶囊之间建议留550—800像素间隔；纵向换行时建议留650—950像素间隔。
- 每个胶囊四周保留250—400像素空白环；不得让说明、REF、音频或视频节点贴近区域边界。
- 每个胶囊外框始终为`3500 × 1500`；通过删减无职责REF、两行排布和缩短说明解决拥挤。无法在保持可读性和2个未来槽位的前提下容纳时，按“素材过载”停止，不扩展外框。
- 连线原则上只在本区域内流动；避免使用远处 MASTER 节点直接拉出跨越多幕的长线。
- MASTER 可用于展示权威母版，但每个镜头仍建立自己的隔离 `REF`。

## 命名规范

推荐稳定格式：

```text
R128｜S03B｜区域说明｜32-44秒｜车损与电话失声
R128｜S03B｜START｜冲洪前状态
R128｜S03B｜END｜皮卡受损
R128｜S03B｜KEYFRAME｜皮卡受损
R128｜S03B｜REF｜儿子38岁
R128｜S03B｜REF｜白色老皮卡
R128｜S03B｜REF｜老旧盘山路
R128｜S03B｜VIDEO｜动作连续版｜网页手动未执行
```

当前节点使用稳定名称；不要用含义不明的 `v2`、`新版2` 或多个同名节点区分状态。

## 素材替换

只有用户明确要求替换某个具体逻辑槽位时才执行原位替换；该请求只授权移除这一槽位的旧资源节点，不授权删除其他节点：

1. 记录旧节点名称、坐标、所有下游连线和提示词中的节点 ID；
2. 删除旧图片资源节点；
3. 确认新文件已在本地生成且符合本轮已解析画幅，再用`libtv upload`在相同名称、相同坐标重建；
4. 恢复下游连线；
5. 把提示词中的旧节点 ID 改为新节点 ID；
6. 核验本地文件哈希、画布资源哈希、视频 `imageListOrder` 和未执行状态。

禁止在旧图旁边再上传一张“新版”却不迁移视频引用。历史图片保存在本地问题归档，不在当前生产区域堆 `ARCHIVE／勿用` 节点。

## 删除边界

删除是独立的难恢复操作。“整理、重排、优化画布”不自动授权删除；必须先获得用户对具体删除目标的明确授权。获得授权后，只有同时满足以下条件，才把节点组判定为可删除的重复分镜组：

1. 属于同一故事版本、同一幕编号和同一时间段；
2. START／END／KEYFRAME、角色、车辆、场景和视频意图构成同一完整组；
3. 新旧两组承担相同生产职责，而不是用户明确授权且仍在进行的临时A/B实验；
4. 已确认其中一组是废弃、落败或错误版本；
5. 当前视频和提示词不再引用待删组。

以下情况不得删除：

- 不同视频单元各自隔离的角色、车辆和场景 `REF`；
- 同一图片在不同视频单元中的独立节点；
- 用户明确授权且仍在进行临时A/B实验的测试节点；
- 只因文件哈希相同、名称相似或画面看起来相似。

删除前先做只读清单，明确保留组与删除组；删除后报告删除内容及可恢复来源。画布删除通常不可直接撤销，本地脚本和素材归档应继续保留。

## 完成验收

- 每个小视频是否拥有精确`3500 × 1500`的独立区域；
- 每个视频单元是否优先为`5–15秒`，且没有只因内部切镜、反打或短闪回产生的`1–2秒`独立VIDEO；
- 每个区域是否除当前节点外仍保留2个未来素材槽和250—400像素空白环；
- 所有图片节点是否均为本地文件上传的`image_resource`，且符合本轮已解析画幅；
- 画布是否没有`image_generate`节点和图片到图片的生成连线；
- 每张图片是否只直接连到所属镜头的视频节点；
- 每张已连线图片是否在具体动作句中有与`mixedListOrder`一致的显式引用；
- 区域内是否能首遍辨认说明、分镜、REF 和视频节点；
- 不同视频单元的 REF 是否保持隔离，没有被哈希去重；
- 每个视频单元是否只保留一个正式动作连续版视频节点，不存在焦段机位版或内部切镜常驻节点；
- 提示词是否只包含可执行、可见或可听指令，没有人物内心、作者解释和观众感受；
- 单视频内部切镜是否按时间段标明景别、切镜方式，并在必要时补机位、角度和呼吸镜头；
- 是否只有同幕完整废弃组被删除；
- 节点名称是否明确指向动作连续版和执行状态；
- 视频的素材顺序、提示词节点引用和实际连线是否一致；
- 未经用户执行前，视频结果 URL 是否为空；
- 画布是否没有孤立新版、失效旧图和无职责归档节点。
