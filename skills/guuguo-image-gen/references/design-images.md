# 设计图生成规则

适用于 UI mockup、玩法/场景概念图、风格探索图、宣发视觉草案、角色/道具设计稿、汇报图、PRD 图、技术方案图等非运行时素材。

## 通用要求

- 设计图通常不需要透明底、色键、切片、九宫格或 Cocos meta。
- 重点写清用途、目标比例、构图、风格、信息层级、文案和参考图角色。
- 如果后续可能拆成素材，提示词里预留边界、留白和可裁切区域；否则不要加载素材后处理规则。
- 占位文字要明确“不要生成可误读的假文案”；正式文案要作为一等输入处理。

## 汇报图 / PRD 图 / 技术方案图

汇报类图片默认是图文一体设计稿，不能为了规避文字难度退化成无文字背景图。纯背景、纯插画或后续另行叠字的场景才生成无文字版本。

默认风格偏好：

- 科技感、精致、清爽、高级，适合正式汇报。
- 深蓝、靛蓝、紫蓝、冰蓝、青蓝之间的柔和渐变，可加微弱光晕、网格、粒子、流光、半透明几何体或空间深度。
- 使用玻璃拟态卡片、半透明面板、柔和描边、轻微内发光、细腻投影和分层景深。
- 插画元素可用 3D 拟态图标、等距科技场景、悬浮数据模块、服务器、云、AI、大屏、机器人、芯片、城市、流程节点等。
- 标题醒目，核心结论、关键数据、阶段进展、风险问题、下一步等模块清晰分区。

## 文案策略

提示词中单独列出“必须准确出现的文字清单”，包括标题、模块名、关键短句、数字、状态名。要求模型逐字呈现这些文字，不添加乱码、伪文字、英文占位或多余文案。

优先生成标题 + 3 到 6 个模块标签 + 每个模块 1 句短说明。若用户提供长文，先压缩成适合入图的短文案清单；长正文保留在 HTML、PPT 或文档正文中。

## 文字容忍与检查

默认相信当前生图模型对正式文字的还原能力，不做逐字验收，也不默认看图复核。

复核时若发现疑似问题，只有错字、乱码、漏字非常明显，且影响标题、核心结论、关键数字、客户可见口径时，才需要修图或重生。不确定时说“疑似”，不要武断判错。

## 比例建议

- 领导/客户汇报封面：优先 16:9。
- 手机长图/战报图：优先 9:16 或 3:4。
- 一页纸汇报：优先 4:3、16:9 或 A4 竖版。
