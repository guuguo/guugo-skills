# 视频字幕制作

把原始视频处理成字幕文字正确、切换稳定、样式一致且画质达标的可交付视频。默认处理中文对白烧录字幕。

## 开工前

1. 读取当前项目的 `AGENTS.md` 及其指向的成片、字幕、内容红线规则。项目规则优先于本技能。
2. 找到原始视频、最终脚本或已确认台词。最终脚本和声音是文字真源；OCR 只用于旧字幕的时间与字框定位，ASR 只用于辅助时间对齐，二者都不能自行改写剧情。
3. **原片归档与工作目录**：
   - 加字幕前的原始视频（剪辑导出无字幕版）统一归档保存至成片目录下的 `原片归档/`（如 `<系列>/成片/原片归档/<单集>-无字幕原片.<ext>`），避免外部文件丢失并形成成片资产闭环。不得覆盖或删除原片。
   - 所有中间文件（ASR、时间轴、ASS、滤镜、抽帧、接触表）以及 **《字幕核对记录.md》必须作为中间产物统一保存在 `成片/中间台/<单集>-字幕工作/` 内部**，严禁将核对记录 Markdown、ASS 或滤镜草稿直接散落在成片交付根目录下，确保成片根目录纯净、仅保留最终可发布成品。
4. 默认使用“完整字幕统一模式”。只有用户明确要求保留正确旧字幕、仅修错字时，才使用局部纠错模式；若作品明确要求无字幕，不得擅自加字幕。

## 标准链路

按顺序执行：

1. 将原片归档到成片目录的 `原片归档/`，并用 `ffprobe` 记录原片分辨率、帧率、时长、视频码率、音频参数和文件体积。
2. 运行 `scripts/resource_preflight.py`，综合当前可用内存、系统内存压力、已有重任务、分辨率、预计抽帧数和工作盘空间决定是否启动。`status=block` 时禁止进入重阶段。
3. 对原片执行本地 ASR，输出包含 segment 和词级时间戳的 JSON。
4. 以 5fps OCR 扫描旧硬字幕，建立整行字幕时间轴，并用 ASR 反查 OCR 漏检区间。只有确认存在旧字幕的事件才设置 `mask=true` 和 `bbox`；无旧字幕事件必须是 `mask=false`。
5. 对照最终脚本逐行修正文字、起止时间、说话顺序、旧字幕字框和无旧字幕对白；处理全部 `unresolved_gaps`。
6. 所有需要烧录文字的视频都要生成字体与字号候选图；有旧字幕时对照原字幕，无旧字幕时在干净原帧上预览。必须查看全分辨率候选，避免字幕过小，选择结果写回 `style.font_review`。
7. 将时间轴设为 `reviewed=true`，从原片一次性完成旧字遮罩与完整字幕烧录。禁止在旧修正版上反复转码。
8. 对修正版执行逐行 OCR 反查，定点抽检所有 `manual_review`、切换边界和旧字闪回风险点。抽帧目检默认按时间顺序合成 `4×4` 多帧接触表，分批查看全部待检帧；疑点再打开对应原尺寸帧，不逐张打开数百张抽帧。
9. 比较源片与成品质量；默认成品码率不得低于原片的 80%。macOS 默认启用 VideoToolbox 硬件加速，未通过时提升目标码率（或软编码降低 CRF）重渲染。
10. 将资源预检报告、时间轴、ASS、滤镜、OCR 验收报告、抽帧接触表以及《字幕核对记录.md》全部完整保存在字幕工作目录（中间产物目录）中；仅可发布成片输出到成片根目录。

执行命令、时间轴修订规则、样式约束和验收清单见 [references/workflow.md](references/workflow.md)。开始实际处理前必须完整阅读该文件。

## 工具路由与自动执行规则

Agent 收到字幕制作请求时，**必须直接自动调用命令**完成全流程处理与验收，严禁只输出命令让用户手动去终端运行。

1. **确定性极速流水线（成熟剧集默认优先）**：
   对于已有确定视觉预设（如《你家的船》系列，预设名为 `"你家的船"`）且原片无旧字幕的常规单集，**必须优先自动调用** `scripts/video_subtitle_repair.py pipeline`：
   ```bash
   SUBTITLE_SKILL_ROOT="${VIDEO_SUBTITLE_SKILL_ROOT:-$HOME/.agents/skills/video-subtitle-workflow}"
   python3 "$SUBTITLE_SKILL_ROOT/scripts/video_subtitle_repair.py" pipeline \
     --video "<原片路径>" \
     --preset "你家的船" \
     [--timeline "<时间轴路径>" | --script "<剧本路径>"] \
     --output "<系列>/成片/<单集>-超清字幕版.mp4" \
     --encoder videotoolbox
   ```
   该命令全自动串联：“原片安全归档 -> GPU 硬件加速压制 -> 多分辨率自适应（480p/720p/1080p） -> 靶向中段抽帧 -> Swift Vision OCR 验收 -> 4×4 多帧接触表拼版 -> 中间台归档”，并在 25 秒内闭环。

2. **通用多阶段调试链路（新剧集/含旧字幕擦除）**：
   若遇到全新未知画风剧集、原片带旧字幕需要局部去字模糊（`mask=true`）、或需要逐步听辨修正对白时，按“标准链路”分步执行 `scan` -> `font-preview` -> `render` -> `verify`。

本地 ASR 优先读取项目的 `docs/harness/rules/local-video-asr-fast-path.md`。若该文件不存在，使用参考流程中的本地 Whisper 模板；模型缓存缺失时明确报告，不要在字幕任务里静默联网下载。

## 不可省略的门禁

- ASR、OCR 扫描、渲染和 OCR 验收默认严格串行；不得同时跑多个视频或多个重阶段。
- 每个重阶段开始前重新执行资源预检。`block` 必须停止，`caution` 只能单任务串行并持续观察内存压力，不能自动降门禁硬跑。
- 长视频、4K 视频或预计运行超过 10 分钟的任务，运行中定期检查 `memory_pressure -Q` 和当前任务 RSS；可用内存低于 10% 时只终止本次启动的精确进程，保留原片和已完成中间产物，不自动重试。
- `reviewed` 未确认或仍有未解决的 `unresolved_gaps` 时，不渲染。
- 只要存在待烧录字幕但未完成字体与字号比对，就不渲染；无旧字幕也不能跳过字号确认。
- 有旧字幕时，只对该字幕实际出现时间内的紧贴字框区域执行局部 `delogo` 去字/模糊修补，不能模糊整条底部或使用贯穿全宽的大底条。
- 没有旧字幕的事件必须 `mask=false` 且不带 `bbox`，不得执行 `delogo`、模糊或其他背景处理，只烧录新文字。整段视频无旧字幕时，滤镜链只能包含字幕渲染。
- 默认字号按方向设定：竖屏约为画面高度 4.5%，横屏约为 5.8%；低于竖屏 3.9% 或横屏 5.0% 视为过小并拒绝渲染，除非用户明确要求小字号并记录 `allow_small_font=true`。
- **低分辨率防糊硬门禁**：严禁在低分辨率视频（短边 `<=720`，如 480p）上使用任何高斯模糊滤镜（必须强制 `blur: 0`），且严禁无描边（`outline: 0`）裸字！低分辨率下汉字笔画像素极少，1px 高斯模糊即会糊死内部笔画细节；必须搭配清晰黑色描边（`outline >= 1.2`，1080p 推荐 `2.0`），确保任何光影下边缘锐利分明。
- **480p 低清成片规避策略**：480p 源片全屏播放必然因像素量不足拉伸发虚；必须优先提醒用户在剪辑端改选 1080p 导出，或在压制时通过 Lanczos 高阶算法升规至 1920×1080 标准画布并以 1080p 标准字号（64px 锐利描边）烧录，严禁直接输出发虚发糊的 480p 成片。
- 长句优先自然换成两行，禁止为了塞进单行而缩小全片字号或明显压扁汉字。字号验收必须查看原尺寸候选图，不能只看缩小接触表。
- 同一句不得拆成单字或半行补丁；相邻整行事件不得短暂重叠。
- 行末逗号和句号不烧录；问号、感叹号等明确语气标点保留。
- 自动 OCR 未通过只表示需要定点人工复核，不能据此自动重做或扩大修改。
- 未完成字幕文字、旧字闪回、音画同步和码率验收时，不声称交付完成。
