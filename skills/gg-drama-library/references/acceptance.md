# 验收标准

## 工具与资料

现有脚本检查配置复用、媒体及时间引用、目录导出和数据快照；运行 `python3 scripts/test_library.py`。这些结果只证明被测试的存储与检查行为。

实际采集验收还须核对：原片版本与视听证据、完整桥段的前后语境、单集情绪及人物知识、整剧阶段与跨集连接、来源视频表现及采集时间。缺集与未知如实记录。结构通过不能代替原片复查，抽样通过不能宣称全剧通过。

采集记录须能按原片呈现顺序读出具体场景、对白、动作、铺垫与后果，并定位其证据；不能只剩标题或结局摘要。角色陈述、可见事实和分析推断分开，分析及标签有本例依据；新采集不生成替换物件、改造建议或通用公式，不用整剧总结填单集字段。

桥段完整性由 Agent 对照原片核验：场景转接、日常动作、对白与反应、必要停留是否在文本中按顺序保住，逐拍证据是否能定位；不能将多场景压成一个回合、跳过铺垫直接写相遇，或以“生活流”标签代替节奏记录。再仅读文本检查能否跟随完整过程及疏密；不按拍数、字数或填满时间轴验收，不凭稀疏帧补停顿。影响理解的缺口未补齐则 partial，结构校验不判断这些语义条件。

声画对应逐句检查：说话人与同期画面有证据，画内/画外/旁白不混同，听话对象与反应如实记录；多人对白未统归一人，也未把画面中的人当作必然说话人。已知时间点、窗口与事实保留，只有缺项标未知；不要求凭空补全，未解决的归属或顺序影响理解时不能标完整。检查上游观察、校对文本、单集事件与桥段引用是否一致，修正传递到受影响记录后再导出目录。

## 素材启发

用真实用户需求和实际库记录检验一份回答：

1. **有依据**：原例可定位，未见或未核实的部分明示；新脑洞与原作事实分开，数据带日期与口径。
2. **有用**：点子具体到人物选择与回应，能说明观众为何想看及与当前需求的联系；人设约束行为可信度，不以首集展示全部性格为验收条件。迁移后的事件分量、前情依赖、动机、信息与关系许可重新成立或明确待定，多段组合的因果与视角连贯。
3. **有差别**：去掉姓名、地点与道具后，仍有不同互动、信息变化或观看获得；换皮版本不冒充多个解法。
4. **能取舍**：人可取局部、组合或继续发散，不必先学会专业诊断；参考与目标冲突时能说明保留、重构或放弃的得失，回应新反馈不丢失已有要求，AI 不替人定稿，也不默认催选方案进入写稿。

资源验收看实际执行记录：普通构思优先使用采集后的文本与标签，不加载图片或运行 ASR、OCR、抽帧；资料有缺口也不自动重采，且不冒充本轮视听核验。用户明确要求视觉核验或补采集时才进入对应分析任务。普通文字读取保持批量与并行能力，不因节省内存退回同题材或前几集匹配。判断电脑内存改善仍须实测相关进程峰值与系统内存压力，不能用规则调整代替结果。

可用真实使用中的困难检查方法是否站得住：源材料与目标情境不同；多个素材落入同一种互动；只有一个可靠原例；保住原效果会违背目标人物，或拼接后改变了故事含义。评价新方案本身是否成立，不把复刻形式当效果保证，也不因需要新设计就判失败。明确只查原例的请求按其范围验收，不强加发散。

真实使用记录用户选取了什么、想组合什么、还缺什么；未获反馈时不声称有效。工具验证、资料核验、创意判断与观众实际反应分别报告，不承诺稳定产出好作品或爆款。
