# 素材启发

## 工作目标

为用户眼前的创作问题增加有用的可能性。参考价值在于它能启发什么；交付价值在于点子之间有哪些值得选择的差别。直接接近的原例可以用，情境不同但局部互动可迁移的材料也可以用。人来定稿。

## 理解与阅读

从用户需求和已有项目事实中，区分全剧人物设定与本轮叙事任务，理解当前的关系、事情与观看感受；不能把完整人设自动变成开头的展示清单。缺少的信息可作为提案假设，不要求用户先填完整人设或选择抽象方向。目标人物与场景约束新构思，用户指定的来源范围才约束原素材。

Harness 从配置目录分批浏览作品、桥段、单集与阶段资料，沿读到的内容寻找有启发的选择、回应、信息安排或后果。原作题材、人物性格、集号和关系阶段是理解语境的依据，不要求与目标整套相同，也不能仅因这些不同就排除整部作品。一部作品、一集或一个完整桥段都可以提供多个参考点。

`index/cases.jsonl` 是全量目录。按文件大小与上下文容量决定整读或分批，独立的文字资料可并行读取，不固定每批条数；避免重复输出已读全文。先由 Harness 理解采集时留下的分析文本和标签，再读候选桥段全文、必要前情、校对对白、画面观察文字、情绪曲线与跨集关系；受众和表现数据按本次判断需要读取。标签帮助理解，不代替语境或变成字符串匹配条件。需要分批时保留游标与候选路径，不做程序化相关性排序或截断候选总数。

目录缺失或与目标记录不一致时直接读 `works/` 真源；只有确需维护目录时才重建，不把 `index`、`status` 或全库 `validate` 当成构思前置步骤。只检查过部分库时，结论限定在实际阅读范围。

原例按采集记录还原其铺垫、互动与后果，再判断可借部分。给用户呈现完整参考时，保留形成观看感受的日常过程、反应停留与场景转接，不能再次压成“某地相遇”或只摘高光对白；记录过粗就注明不足，不靠新构思补成原作。历史 mechanism、替换建议或适配结论不作为原作事实；它们缺失也不妨碍构思，由 Harness 根据具体事件判断，不要求采集端预先给创作答案。

## 资源约束

构思阶段使用采集后的文字与标签，默认不打开原帧、接触表或视频，也不运行 ASR、OCR、抽帧。引用画面时使用已有观察文字和时间定位，以普通链接提供证据入口，不为展示出处自动内嵌图片。使用已有分析须保留其覆盖范围、来源和不确定性，不宣称本轮重新看过原片。

文字记录缺失、矛盾或不足以支持某个判断时，标明缺口，换用有依据的参考或将新点子注明为假设；不以“保证准确”为由自动重采或加载图片。用户要求看图、核对原片或补采集时，再作为对应分析任务调用 gg-video-analysis，优先复用已有证据，仅处理所需范围；看图不连带启动 ASR，媒体处理沿用该技能的资源规范。普通构思保留文字批量与并行读取能力。

## 从参考形成点子

先理解原例为什么值得看：事件对人物有什么分量，观众想知道或等待什么，人物选择与信息安排怎样形成这种期待。再判断其中什么能服务目标故事。句式、物件、动作顺序或隐藏身份的形式相似，不代表观看吸引力相同；换掉关键事件或成立条件后，应重新判断新方案的作用，不宣称继承了原作效果。原作热度不能单独验证某一钩子的因果作用，新方案尚未验证也不等于不成立。

迁移时为新人物建立动机、信息与关系许可，说明借用部分、新建条件和得失。后段桥段可用于启发开头，但须检查其选择依赖的前情在新情境中是否成立；不能只抽出一个性格词，就把另一种动作称为同一桥段的迁移。若原效果依赖的行为与目标人物冲突，可以只借局部、换一种事件或放下该参考；不靠事后增加照顾、反应或解释，默认抵消前面行为的含义。保留、重构与放弃都属于正常取舍，用户明确锁定的要求之间若有冲突，说明冲突而不擅自更改。

多段或跨集组合后，按同一个故事检查：谁知道什么、为什么采取下一步行动、物件和关系留下什么后果，以及叙述者的视角和态度是否连贯。对白、动作与说话人应在新情境中重新成立，不原样携带已失去对象或动机的句子。旁白与场内对话可以交替；重复句式或固定旁白位置不能代替因果与叙述视角的衔接。

每条点子先找到值得发生、值得观看的事情，再判断这些人物在此情境中怎样选择和回应，写到让人能想象哪个瞬间可能有趣、动人或意外。人设约束行为是否可信，不规定每集必须展示哪些性格。尚未表现一种性格不等于违背人设；除非用户明确要求本集突出，否则不为补齐性格而额外制造拒绝、争执或证明动作。人物特质可随有意义的事件逐步显露，目标人设允许多种有来由的表现。

同时比较本轮点子。暂时遮住姓名、地点和道具，如果剩下的冲突、选择与回应仍相同，就把它们视作同一解法的变体。保留真正增加选择的点子，其余合并；新增探索朝尚未出现的互动、信息变化或观看感受展开，不靠凑数量制造丰富感。这是 Harness 的内容判断，不设置打分程序或分类配额。

同一参考可启发多个不同解法，不同参考也可组合；点子数量、素材跨度和说明详略服从当前需要。尊重用户明确边界，暂未解决的前提作为假设交给人判断，不将灵感伪装成已验证可拍的成稿。

## 交付与继续

把真实参考和具体点子直接给用户，不要求先选方向，也不默认挑出一条最省事路线。让人看清每条值得拿走的部分：

- 新情境中的具体互动与可能的观看获得。
- 借自哪部作品、哪集、哪一回合，附已有对白/画面/时间段入口；多个点子共用来源时只介绍一次原例。
- 为迁移改变或补足了什么，尚有哪些假设。引用表现数据时附来源、采集时间和可比依据，详见 [数据快照](performance-data.md)。

版式不固定，原例介绍与点子可相邻展示，方便比较。用户只查原例时不添加创意；库内材料不足而仍需发散时，可另列无库内出处的纯构思。灵感阶段保持可比较、可继续发散，不默认以“选一条就写可拍脚本”收尾；用户明确要求写稿时再进入写稿任务。

收到反馈时，先结合已有目标判断它影响的是表达细节、互动动机、观看期待还是整体衔接，再决定调整当前点子、重新构思或换参考。说明改动保住和牺牲了什么，并回看此前已确认的要求；不能只顺着最新一句评价修改，再将旧问题引回。用户说“没感觉、再来一些”时，扩大不同可能性，不强求专业诊断，也不自动改完整稿。

将来源、探索范围、点子和实际反馈保存到现有项目查询记录，字段见 [数据契约](data-contract.md)。收藏或觉得有意思不等于已采纳剧情；只有人明确确认的内容才进入定稿状态。
